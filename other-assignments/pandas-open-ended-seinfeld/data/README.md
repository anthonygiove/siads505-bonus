# Data dictionary

Three CSV files. `lines.csv` joins to `episodes.csv` on `episode_id`, and to
`characters.csv` on the **cleaned** speaker name that Question 2 produces.
**The corpus is simulated** — see the note at the bottom before you quote any
of it.

## `lines.csv` — 26,389 rows, one per line of dialogue

| column | type | notes |
|---|---|---|
| `line_id` | string | `L00001`, unique, in script order |
| `episode_id` | string | joins to `episodes.episode_id` |
| `scene_no` | int | scene within the episode |
| `line_no` | int | line within the episode |
| `location` | string | 17 of them; availability changes across the run |
| `speaker` | string | **as the script supervisor typed it** |
| `dialogue` | string | the line, sometimes with a stage direction in it |

### Deliberate messiness

Almost every question in this assignment exists because of something in this
list:

- **234 distinct strings in `speaker` stand for 89 speakers.** `JERRY`,
  `Jerry`, `jerry`, `JERRY:`, `  JERRY `, `JERRY (V.O.)`, `GEORGE [entering]`,
  `KRAMER  (cont'd)`. Note the double space in that last one: removing the
  annotation leaves it behind, so a rule that strips but does not *collapse*
  whitespace produces `"KRAMER "`, which is not `"KRAMER"`. Question 2.
- **105 lines are credited to two people at once** — `JERRY AND ELAINE`,
  `GEORGE & WAITRESS`. The cleaning rule in Question 2 leaves them as a single
  speaker with a strange name, which means they show up in Question 5's cast
  lists as though they were a person. That is not a bug to be fixed silently;
  it is a thing to notice and write down.
- **Stage directions live inside the dialogue**, in round or square brackets,
  either wrapped around a line or as the whole line. **496 lines are nothing
  but a stage direction** and contain no spoken words at all. Question 3.
- **Nothing says who is in an episode.** There is no cast table, no scene-level
  appearance list. "Appears in" has to be inferred from "speaks in", and where
  you draw that line changes the answer: at a one-line threshold the typical
  episode has 6.6 characters in it, at three lines 4.3, at twelve lines 3.8.
  **345 (episode, character) pairs have exactly one line.** Question 5.
- **Elaine is not in season 1.** Five episodes where a lead's share of the
  dialogue is genuinely zero, and where `0.0` and `NaN` mean different things.

## `episodes.csv` — 180 rows, one per episode

| column | type | notes |
|---|---|---|
| `episode_id` | string | `S04E17` |
| `season` | int | 1–9, with 5/12/23/24/22/24/24/22/24 episodes |
| `episode_in_season` | int | |
| `episode_overall` | int | 1–180, air order |
| `title` | string | 180 distinct |
| `air_date` | date | |
| `writers` | string | **one or two names separated by ` \| `** |
| `director` | string | four of them; the show changes hands after season 5 |
| `runtime_min` | int | 22, 23, or 44 for the double-length episodes |
| `us_viewers_millions` | float | **14 missing** |
| `imdb_rating` | float | **6 missing** |

**65 of the 180 episodes are co-written**, which is why Question 8 has two
answers: crediting each writer fully totals 245, splitting the credit totals
180. Only the second gives you a column you can turn into a percentage.

**The 14 missing audience figures are the whole of Question 6.** They are not
missing at random in a way that lets you ignore them: the audience climbs
steadily from roughly 13 million in season 1 to roughly 33 million in season 9,
so filling a season 9 gap with the series median understates it by about eight
million.

## `characters.csv` — 34 rows, one per character

| column | type | notes |
|---|---|---|
| `character` | string | the canonical upper-case name — what Question 2 produces |
| `full_name` | string | blank for the walk-on parts |
| `role` | string | `main` (4), `recurring` (14), `guest` (13), `mentioned` (3) |
| `first_season` | int | |

**Three characters never say a word.** They are `role == "mentioned"` — people
everybody talks about who are never on screen. They are on the list so that a
`how="right"` or `how="outer"` merge has something to invent, and so that
Question 9 has a reason to filter on `role`.

## Provenance

Generated by `../tools/generate_data.py` with seed **1989** (the year the pilot
aired). The generator is deterministic — rerun it and you get byte-identical
files.

Real: the nine-season, 180-episode structure and the episode counts per season;
the character names and their roles; the writers; the directors.

Simulated: **every line of dialogue**, every episode title, every air date,
every audience figure, every rating, every writing and directing credit, and
every location assignment. The dialogue is assembled from templates and word
banks; a handful of the show's famous catchphrases were sprinkled through it so
that Question 7 has something to find. **Nothing in `dialogue` is a real
quotation from the show apart from those short catchphrases, and none of the
numbers are real.**
